# CRM Call Sync — private test build

This is a **separate application** from the local-only CRM Call Test probe. It is an experimental debug build, not a production release. Do not enable call sync on a live CRM or enroll real staff/customer data until this build is verified on actual phones and a separate test CRM. Installing it does not update or replace the old probe.

## What it does

After informed consent, two Android permissions and CRM login, the app registers a device and securely stores its device token using Android Keystore. It only scans for calls **started after enrollment**, never audio. For identifiable SIM account entries, it queues incoming/missed calls locally as encrypted data and sends batches with stable retry IDs. An empty queue generates no API request. It requests a local scan after call-log changes and about five minutes after the previous timer. Android can postpone, restrict or stop background jobs, especially under battery saver, Doze, force-stop or vendor restrictions; these times are **not guaranteed**. Failed network uploads use exponential backoff; unacknowledged individual events remain queued and are deferred to avoid blocking other calls. Device revocation or a disabled account stops further uploads when detected. No continuous server polling occurs, so revocation is noticed on the next upload attempt.

The app identifies SIM calls through Android's phone-account SIM capability. If an OEM omits or hides that information, or the number is private/invalid, the entry is skipped rather than guessed. The status screen counts skipped entries; it doesn't display phone numbers. Calls not delivered or not recorded cannot be synced. WhatsApp and outgoing calls are not imported. Call-log presentation, call-waiting, multi-SIM handling and background behavior vary by phone/carrier and **must be tested**. It does not guess a SIM slot. Some devices update call-log duration after an entry appears; the app captures the value available at scan time.

Stopping sync deletes the local pending queue and attempts to revoke the device token; when offline or if the revocation endpoint fails, an administrator must revoke that device in the CRM. Already-sent CRM data is unaffected. Permission may also be revoked in Android Settings; until restored no call logs will be read.

## Safe testing

1. Set up an isolated test backend from this branch with a separate test database and test accounts. Run migrations and seed as documented in the main README. In the *test backend only*, set `CALL_EVENT_AUTO_CREATE_LEAD=true` and deploy. This setting defaults to false; the new sync endpoint rejects uploads when false. Never set this on live until testing and a deployment decision are complete.
2. Set the GitHub repository Actions variable `CRM_SYNC_ORIGIN` to the test backend's **HTTPS origin only** (for example `https://your-test-host.example`, with no path or trailing slash), or set the environment variable locally before building. The APK's login screen displays the origin. If not supplied, the build points to the existing production frontend; the feature gate prevents registration while the feature is not deployed or is disabled, but **do not turn it on there merely to test**. Build only from a trusted repository and verify the displayed origin before entering credentials. Never share credentials in chat.
3. Run the **Android call feasibility build** workflow on this branch. Download and extract the `CRM-call-sync-test-debug` artifact. The artifact expires after seven days. The `CRM-call-feasibility-debug` artifact is the old diagnostic, not this app. A debug build is signed with an ephemeral CI debug key: it is for private testing only, and future builds may not upgrade it without uninstalling. Uninstalling deletes unsent calls and resets its device identity; ask the administrator to revoke the old device first. For release, create and protect a real signing key and provide an update/distribution plan.
4. Enroll a consenting test phone using a test account. Verify an incoming call, missed call, two calls close together, and a waiting call received while already talking against the native call log. Test with call waiting disabled and on different Android/OEM/SIM combinations. Verify one open lead and call timeline, and a new returning-contact lead with authorized history after conversion/loss.
5. Go offline for multiple calls, then reconnect and check all eligible calls arrive once. Retry and restart the phone; test force-stop and reboot, permission denial/revocation/restoration, server errors, disabled flag, disabled employee and revoked device. Observe status and skipped counts; test battery saver and long periods in background. Confirm no empty requests and batched deliveries. A force-stopped app may not run until reopened.

Google Play places significant restrictions on call-log permissions; distribution eligibility is not established. Do not use this debug APK for production or make claims of general reliability before real-device tests, security review and release signing.
